# CONCEPT — 《适航》（Airworthiness）

> 一句话：你是一家从没造过喷气客机的中型厂的新任项目总师，用 34 个月把一张图纸变成航司机队里的第 25 架飞机。

## 1. 锁定值与开放维度

锁定值见 `PRODUCT_BRIEF.md` 第 2 节。概念阶段真正存在取舍的只有一件事：**玩家坐在产业链的哪把椅子上**。其余维度由这把椅子决定。

## 2. 核心体验承诺

| 项 | 内容 |
|---|---|
| 承诺 | 让玩家亲手经历"订单签下来却交不出去"的全过程，并在结束时能解释民航制造为什么是产能、供应链与取证的三重约束游戏 |
| 兑现成功的样子 | 玩家在第 6 回合主动说"我不能再接单了，我先解决 2 号工位"；在第 12 回合能算出自己每架飞机的真实毛利，并知道亏在哪 |
| 兑现失败的样子 | 玩家全程只在点"下一回合"，看数字变大变小，说不出任何一个环节为什么卡住 |

## 3. 候选概念卡

### 候选 A：《适航》—— 整机厂项目总师（**选定**）

| 维度 | 内容 |
|---|---|
| 主品类 | 回合制经营模拟，单局 12 回合，每回合 = 1 季度 |
| `experienceProfile` | `system-led`（决策依据是节拍、库存、现金流、取证进度这些可计算的量；叙事只提供任务语境） |
| 借用的成熟交互 | 借鉴《异星工厂》的"瓶颈定位"思维、《大亨》系列的季度报表与合同系统、《Papers, Please》的"审阅-盖章"动作质感（用于取证问题单） |
| 舍弃 | 实时产线、传送带、3D 工厂漫游、员工个体养成、多人联机 |
| 玩家身份 | 北辰航空 P-19 项目总师，向董事会负责 |
| 核心动作循环 | 每回合：读上季结算 → 定本季节拍与采购 → 处理停线与问题单 → 谈单/改单/弃单 → 结算现金与信誉 |
| 压力来源 | 在手订单的交付窗口 vs 实际月产率；发动机长周期件到货 vs 总装节拍；取证里程碑 vs 首架交付承诺 |
| 执行阻力 | 工位节拍不能瞬时提升（学习曲线）；供应商有最小起订量与预付；每加速一次质量下降一档；取证问题单必须逐条闭环才能拿证 |
| 失败后果 | 违约赔付、订单取消、信誉下降导致后续客户要求更高折扣；现金为负则董事会接管（游戏结束） |
| 世界反馈 | 航司会因你的延期改签竞品；租赁商趁低价抄底你的机位；供应商在你拖欠后降低排产优先级；已交付机队的可靠性数据反过来影响新单 |
| 原著/现实结构如何变成操作 | "双寡头压价"变成客户谈判里的价格锚；"发动机卡产能"变成必须提前 3 回合锁定的长周期件；"取证门槛"变成 12 项科目的问题单闭环 |
| 招牌画面 | 第 2 号工位亮红灯、整条脉冲线停住，右侧账本上三张订单的交付倒计时同时变成琥珀色 |
| 最小验证片段 | 1 个机型、4 个工位、3 张订单、12 回合，纯白盒表格 + 一张脉冲线示意图 |
| 最大设计风险 | 数值一旦不透明，玩家会把"交不出去"误读成随机惩罚，学习价值归零 |
| 推翻判据 | 若白盒测试中 5 名玩家有 4 名无法在停线后指出"是哪个决定导致缺件"，则本方向需改为显式因果链更强的形态 |

### 候选 B：《采购单》—— 航司机队规划与采购（淘汰）

买方视角：玩家为一家航司规划机队，比较座级、航程、残值、租赁 vs 自购。

- 优点：决策对象直观，学习"为什么航司买这个不买那个"很直接。
- **否决理由**：世界反馈基本只有账面数字与合同条款，玩家动作无法制造"看得见的局面变化"；与 A 的谈判子系统高度重叠，作为主方向规模不划算。**保留为 A 的商务子系统**（玩家坐在卖方，但必须理解买方怎么算账）。

### 候选 C：《入轨》—— 航天发射服务商（保留为第三章）

玩家经营一家发射服务商，卖发射、拼单、复用。

- 优点：与民航共享能力底座，现实数据极有戏剧性（一家占全球 50.8% 发射次数）。
- **否决为主方向**：用户主诉求是"飞机制造厂商"，且航天市场是"挑战垄断者"的单极结构，玩家操作空间被现实结构压得很窄；商业闭环（卖发射位）比卖飞机短，学不到完整的制造-取证-交付链条。**保留为 A 的第三章：把总装能力迁移到箭体，学"复用 vs 一次性"的成本交叉点**。

### 候选 D：《全链》—— 从零件到航司运营的全产业链大亨（硬否决）

**否决理由**：范围超出 `PRODUCT_BRIEF.md` 预算上限（系统数量翻倍、内容量为 3–4 倍），且必然退化为"每个环节都点一下"的浅层模拟。属于硬否决项中的"最小可玩范围超出限制"。

### 候选 E：《停飞》—— 一次事故调查的互动叙事（硬否决）

玩家作为调查组成员，通过证词与记录还原一次停飞事件。

- **否决理由**：核心规则只停留在过场与证词里，玩家不做机制决策，无法达成"了解生产制造与销售运营流程"的承诺。属于硬否决项中的"原著核心规则与核心玩法循环脱节"。可作为 A 的**事件包装**（一次质量事件用调查式叙事呈现），但不做主方向。

## 4. 硬否决筛查结果

| 候选 | 否决项 | 结果 |
|---|---|---|
| A | 无 | 通过 |
| B | 世界反馈仅数字 | 淘汰为主方向，保留子系统 |
| C | 与用户主诉求偏离、操作空间窄 | 淘汰为主方向，保留章节 |
| D | 范围超预算 | 硬淘汰 |
| E | 玩法与核心规则脱节 | 硬淘汰，保留为事件包装 |

## 5. 核心取舍

选 A，等于用**"卖方视角 + 产能约束"**换取学习深度，代价是牺牲了"开飞机/看飞机"的直观快感。这个取舍成立，因为用户要的是"了解流程"，而流程的真相恰恰在卖方这一侧：**航司看到的是交付仪式，制造厂看到的是 34 个月的排产表。**

第二个取舍：**回合制而非实时**。实时产线更好看，但会让玩家盯着传送带而不是盯着约束；回合制才能让"这一季我选择先解决哪个瓶颈"成为唯一的、必须做的决策。

## 6. 玩家能动性保障

| 权力 | 兑现方式 |
|---|---|
| 因果权 | 接不接单、锁多少长周期件、爬产多快、先闭环哪个问题单，全部由玩家定，且都在 2–4 回合后产生可见后果 |
| 结算权 | 每个后果都能在结算报表里指到具体一行：这一架为什么晚交 41 天，缺哪个件、欠哪个工位 |
| 不可妥协底线 | 任何一次延误都必须有可追溯的玩家决定；纯随机只允许出现在"外部事件"上，且必须提前 1 回合预告 |

## 7. 最小验证问题

1. 玩家在第 3 回合能否独立发现"我的瓶颈是 2 号工位，不是订单不够"？
2. 玩家能否在不知道公式的情况下，凭界面信息判断"这一单该不该接"？
3. 玩家在第 12 回合能否说出自己每架飞机的毛利构成？

## 8. 待解问题

- 取证系统的深度：做成"逐条问题单"还是"里程碑计数"？前者学习价值高，后者操作成本低。倾向逐条，但限制每回合最多 2 条。
- 航天章节是否独立存档：倾向作为第三章接在同一局之后，用同一批工位。
- 叙事层是否需要人物：`system-led` 项目不需要角色扮演，只需要一个"董事会"作为压力来源的声音。
