# GAME_DESIGN — 《适航》（Airworthiness）v2

> 输入：`SOURCE_BIBLE.md`、`PRODUCT_BRIEF.md`、`CONCEPT.md`、`航空制造组织与流程手册.md`
> 18 个季度、单人离线、回合制经营模拟。玩家是北辰航空 P-19 项目总师。
> v2 的主要变化：把抽象的"取证科目"换成真实的研发—制造—试验—试飞—取证五道门，加入五个专业部门的产能分配。

## 0. 序章与立项

玩家不是在一个"已经设计到一半"的项目里接手，而是从一个具体的人、一家具体的公司开始。

| 序章屏 | 内容 | 作用 |
|---|---|---|
| 1 | 北辰航空三十七年，两千一百人，从修涡桨起家 | 交代身份与厂史 |
| 2 | P-7 涡桨还在卖，但市场每年萎缩 6% | 交代危机 |
| 3 | 行业只有三个位置：双寡头、第三极、夹缝 | 交代格局 |
| 4 | 前任总师老周被换掉，留下一本笔记本 | 交代代价与传承 |
| 5 | 董事会给 18 个季度、25 架的目标 | 交代胜负条件 |
| 6 | 五个部门各自负责什么，不能互相借人 | 交代团队 |
| 7 | **立项选择一：站在哪个位置**（96 座缝隙 / 130 座主流） | 决定订单量与折扣 |
| 8 | **立项选择二：怎么造**（全新设计 / 改型衍生） | 决定研发成本与工作量 |

两个立项选择立刻改变开局数值：

| 选择 | 效果 |
|---|---|
| 96 座 | 订单量 ×0.85、折扣少 2 个点、竞争少 |
| 130 座 | 订单量 ×1.1、折扣多 2 个点、正面撞 E-22 |
| 全新设计 | 研发 0.7 亿/季、信誉 +6、三项工作按全量做 |
| 改型衍生 | 研发 0.5 亿/季、信誉 −5、数字样机/静力/包线三项各减 1 |

这一层让"这家公司从哪来、为什么做这个型号"变成玩家自己按下的一颗按钮，而不是文档里的一段设定。

**配图**：八屏里四屏各带一张线稿插图（厂区外景 / 车间筒段 / 董事会白板 / 首飞跑道），情节节拍中的「第一位客户」「老周的笔记本」「首飞」也复用同组插图。插图只做氛围，不承载信息。

### 0.1 新手目标清单

进入游戏后的前四季，界面顶部常驻一条目标清单，把"现在该做什么"写成祈使句：

| 季 | 目标 |
|---|---|
| 1 | 选一个融资方案 / 到「技术流程」把产能派出去 / 点「提交本季」 |
| 2 | 到「采购」锁定第一批发动机 / 继续派工并提交 |
| 3 | 到「商务」接下第一张订单 / 看一眼「本季建议」 |
| 4 | 投一次扩线 / 招一个人 |

完成项打勾并划掉，右上角显示 `2/3`。第 5 季起自动消失；玩家也可以点「知道了」提前关闭，或在 HUD 关掉引导模式。

## 1. 体验与核心循环

### 1.1 玩家身份与体验目标

| 项 | 内容 |
|---|---|
| 玩家扮演 | 北辰航空 **P-19 项目总师**：管五个部门、一条总装线、一本订单账 |
| 核心体验目标 | 亲手把一架飞机送过 **设计冻结 → 首架试飞机下线 → 首飞 → TC → PC** 五道门，再把它变成航司机队里的第 25 架 |
| 目标情绪 | 前半程是"我明明在推进，为什么一分钱没进来"，后半程是"门开了，产能和现金才刚开始追我" |
| 情绪落点 | 关掉游戏后能讲清楚：TC 和 PC 差在哪，为什么拿到 TC 还是交不了货 |
| `experienceProfile` | `system-led` |

### 1.2 核心循环（每回合 = 1 季度，共 18 回合）

```
读上季结算（哪道门没动、现金还剩几季）
  → 技术流程（把五个部门的产能派到能推进的工作项）
  → 产线与采购（扩不扩线、锁不锁发动机、加不加班）
  → 商务（接单 / 拒单 / 转租机位）
  → 结算（工作完成、门解锁、交付、收付款、违约）
  └→ 回到第一步，且局面已不可逆地改变
```

### 1.3 主要玩法对标与取舍

| 先例 | 借用 | 舍弃 | 理由 |
|---|---|---|---|
| 《异星工厂》 | 瓶颈定位：整条链的产出由最慢的一环决定 | 实时物流、传送带 | 玩家要学的是"哪一环卡住" |
| 《铁路大亨》类经营模拟 | 季度报表、合同与违约金、资本支出回本周期 | 地图铺设、股价操纵 | 封闭局更适合学习目标 |
| 《Papers, Please》 | 「审阅—盖章」的动作质感，用于适航问题单与门评审 | 道德困境叙事 | 只借动作手感 |
| 项目管理类桌游 | 前置依赖与关键路径 | 随机事件牌堆 | 本作事件确定性排期，可复现 |

### 1.4 真实流程如何变成玩家动作

| 真实结构 | 玩法形态 |
|---|---|
| 部门按专业划分，产能不可互换 | 五个部门各有独立产能，设计部的人不能去开试飞机 |
| 试飞按架次而不是按人算 | 试飞部产能单位是"架次/季" |
| 前置依赖构成关键路径 | 19 个工作项带 `req` 列表，前置没完成就派不进去 |
| TC 是设计准入，PC 是生产准入 | 两证分开；TC 之后产线可生产，PC 之后才能交付 |
| 长周期件决定爬产上限 | 发动机提前 3 季锁定，只能整批 |
| 预付货款养产线 | PDP 按交付位提前 3 季开始收 |

## 2. 世界规则与进程

### 2.1 五个部门

| 部门 | 产能单位 | 初始 | 上限 | 负责的工作 |
|---|---|---|---|---|
| 设计部 | 人 | 2 | 4 | 系统布置与数字样机、设计冻结评审 |
| 制造工程 | 人 | 1 | 3 | 工装与型架、首架试飞机总装 |
| 试验部 | 人 | 1 | 3 | 全机静力、铁鸟台联试、疲劳 |
| 试飞部 | 架次/季 | 2 | 4 | 首飞、包线扩展、失速颤振性能、噪声结冰 |
| 适航部 | 人 | 1 | 3 | 审定基础、结构/系统/试飞符合性文件、TC、PC |

增聘一人 0.8 亿，当季到岗。产能不可跨部门挪用。

### 2.3 五道门

| 门 | 完成条件 | 解锁什么 |
|---|---|---|
| G1 设计冻结 | d4 | 工装可以开工 |
| G2 首架试飞机下线 | m2 | 试验与试飞有实物 |
| G3 首飞 | f1 | 包线科目可开始 |
| G4 TC | c5 | 总装线开始生产（但不能交付） |
| G5 PC | c6 | 可以交付 |

**TC 与 PC 之间有至少 1 季的空转期**：产线在造，现金在烧，一架上不了航线。这是本作设计的核心痛点。

### 2.7 决策辅助工具

玩家每季要同时管五条线，光靠记是管不住的。界面提供三个工具，都不替玩家做决定：

| 工具 | 位置 | 做什么 | 不做什么 |
|---|---|---|---|
| 关键路径条 | 右侧「项目阶段」卡下方 | 列出到下一道门的关键路径；实心点＝现在就能动，空心点＝被前置挡住 | 不排序优先级，不告诉你哪个更划算 |
| 预测（12 季） | 同上 | 克隆当前状态，按"不追加投入"推演，给出预计 TC / PC / 首架交付 / 现金最低点 | 不含玩家未来的招聘、扩线、新订单 |
| 自动派工 | 同上 | 按关键路径优先填满本季部门产能 | 可随时手动改，不锁定 |
| 本季建议（引导模式） | 决议面板顶部 | 给出 1–5 条具体动作（派工/招人/扩线/锁件/接单），可一键全部执行 | 只在引导模式开启时出现，随时可关 |

外加一条常驻的「本季判断」：用两句话说明下一道门是什么、当前缺口是什么。

预测是本作最有教学价值的一个数：在 T1 点开，它会告诉你"按现有产能 12 季内拿不到 TC"；同一时刻招五个人再点，TC 会跳到第 11 季。**它把"人多力量大"从口号变成了一个可比较的数字。**

### 2.8 事件与故事

| 类型 | 数量 | 机制 |
|---|---|---|
| 随机事件 | 12 张牌，每局按种子抽 4–5 张 | 提前一季预告，生效当季播报；覆盖供应链、局方、客户、内部、外部五类 |
| 情节节拍 | 9 个固定节点（T3/5/7/9/11/13/15/16/17） | 6 段纯叙事（只给一句结果）+ 3 次抉择（二选一，改质量/信誉/进度） |
| 种子 | 每局一个 5 位数 | 显示在结算页脚，同一颗种子可复现同一局 |

事件不是惩罚，是**外部约束的显性化**：竞品降价让你重新想折扣，发动机延迟让你重新想锁定节奏，关键工程师离职让你意识到产能不是天生的。

三个抉择节拍对应三种真实张力：供应商晚宴要不要提前锁第二批、首飞前要不要为一项风险推迟两周、第一张问题单要不要补飞一个架次。它们不给最优解，只给代价。六段叙事则负责把"客户来访、老周的笔记本、局方进场、首飞、客户催货、董事会前夜"这些真实时刻放进来——它们只给一句结果，不增加决策负担。

### 2.8.1 回响、航司侧与航天切片（本轮新增）

| 系统 | 实现 |
|---|---|
| 叙事回响 | 三个抉择写入 `echoFlags`/`echoes`；两个条件节拍（第 12、16 季）只在做过对应选择时出现；结算里追加 `【回响】` 说明因果 |
| 航司侧 | 四个航司档案（机队/已交付/关系/可靠性）；「客户」页可花 0.4 亿拜访，关系 +8，关系越高折扣越浅；交付后每季产生可靠性评分，回流信誉 |
| 音效 | WebAudio 合成，无音频文件；HUD 有开关与音量；无 AudioContext 时静默降级 |
| 航天切片 | 结项页进入「第三章」，8 个季度、12 发合同，对比一次性与可复用；含研制期现金低点与 6.25 发回本点；不含 TC/PC、客户谈判与工位排产 |

### 2.8.2 项目助理（前三季 RPG 式引导）

| 项 | 设计 |
|---|---|
| 角色 | 林工，项目助理；第 1–3 季共 9 步对话，之后不再插话 |
| 形式 | 左下浮层：头像 + 对话气泡 + 一句「下一步」 + 至多两个可执行选项（含跳转对应页签） |
| 节奏 | 第 1 季：界面分区 → 融资 → 派工 → 提交；第 2 季：发动机前置期 → 关键路径与预测；第 3 季：订单窗口 → 客户关系 → 收尾交接 |
| 控制 | 每步最多两个选项，随时「跳过引导」「回看」；重开清空进度 |
| 边界 | 不接管回合，不替玩家决策；只解释各界面如何影响目标 |

### 2.9 降低决策成本的三个做法

1. **引导模式默认开启**：决议面板顶部直接列 1–5 条可执行动作，一键执行后仍可手改。想自己算的玩家可以关掉。
2. **叙事节拍不参与决策**：9 个节拍里 6 个是纯叙事，读完点继续即可，只在后台给一个很小的数值。
3. **每季只做一件事的错觉**：关键路径条把"下一道门"顶到最前面，玩家不需要同时权衡 17 个工作项。

## 3. 决策与关卡节拍

| 幕 | 回合 | 核心决策 | 取舍 |
|---|---|---|---|
| 一·设计收口 | T1–T4 | 先派设计还是先派试验 | 设计不冻结，工装开不了工；先做试验能提前暴露问题但要等设计输入 |
| 二·首架与地面 | T4–T8 | 招不招人、招哪个部门 | 四个部门同时缺人，钱只够招两个 |
| 三·试飞 | T7–T11 | 试飞架次怎么分 | 包线、失速颤振、噪声结冰三条线共用每季 2–4 个架次 |
| 四·取证 | T9–T13 | 适航部投多少 | 它是唯一把"做了试验"变成"局方认可"的部门，最容易被忽视 |
| 五·量产 | T13–T18 | 产能、发动机、接单 | TC 到手不等于回款，PC 之前全是净流出 |

### 3.1 必须存在的张力局面

1. **T4 的招聘抉择**：设计、制造、试验、适航四个部门同时缺人，现金只够招两个。招错的代价在 5 季后才显现。
2. **T8 的架次分配**：试飞部每季 3 个架次，包线要 2 个、失速颤振要 3 个、噪声结冰要 2 个。先开哪条线决定 TC 什么时候到。
3. **T10 的加试单**：局方要求补做客舱线束复核，要占 1 个适航部人力。不处理就一直挡 TC。
4. **T13 的空转期**：TC 到手，产线开动，但 PC 还没下。看着飞机一架架造出来却收不到钱。

## 4. 反馈、失败与重开

- 每道门在界面右侧有独立的行，通过后转青；当前门在上方门条里琥珀高亮。
- 工作项卡片显示 `已完成人季/需求人季`，前置未满足时左侧转红并写明缺哪一项。
- 每季结算给出**归因句**：为什么本季交付 0 —— 未取证 / 待 PC / 发动机不足 / 停线。
- 失败归因必须指到具体决定。例："第 13 季交付 0：已取 TC，但 PC 还没下来。局方要确认你能稳定造出合格的飞机。下一步：PC 生产许可证。"
- 重开回到完全相同的初态：`cash 2.0 / 五部门 2-1-1-2-1 / 19 个工作项清零 / 无 TC 无 PC`。

## 5.5 图鉴（沉浸层）

15 件真实部件的矢量线稿，分五组：机体结构、机载系统、动力装置、工装与设备、试验设施。每件给三行规格、一段原理、一句"在游戏里对应什么"。

图鉴不是装饰：它是把"项目管理"接回"飞机本身"的那一层。玩家在技术页点「全机静力试验」时，能在图鉴里看到静力加载台长什么样、加到 150% 极限载荷是什么意思。

## 7. 最小可运行规则与复现路径

### 7.1 最大设计风险

**流程被玩家读成"点按钮等进度条"。** 缓解：每个工作项都必须写明产出物与前置，门条必须显示"下一道门 + 当前缺口"，让玩家每一季都在回答"我现在该把钱和人放在哪一环"。

### 7.2 关键公式

| 量 | 公式 |
|---|---|
| 学习曲线 | `L(n) = max(0.45, n^-0.2345)`，n = 累计交付 + 1 |
| 季度产能 | `cap = k × 90 / (60 × L(n))` |
| 单机成本 | `cost = 2.72 − 0.25 × (1 − L(n))` |
| 单机收入 | `price = 4.20 × (1 − discount)` |
| PDP | 计划交付前 3 季 15%、前 1 季 20%、交付 50%、后 2 季 10%；定金 5% |
| 违约 | 每架 5% 合同价 + 退还已收 PDP 的 90% |
| 生产闸门 | `tc` 之前不产出；`pc` 之前不交付 |

### 7.3 复现路径（主线）

## 8. 验证范围与通关路径

### 8.1 可玩范围

1 个机型项目，18 个回合，8 屏序章，2 个立项选择，5 个部门，17 个工作项，5 道门，4 张订单，9 个情节节拍，每局随机 4–5 个事件。

### 8.2 明确非目标

不做：航司运营、航线排班、3D 工厂、员工个体养成、多人联机、真实事故还原、真实品牌素材、第三章航天关卡（只留设计接口）。

### 8.3 一条完整通关路径

见 7.3。第 12 季取得 TC，第 13 季取得 PC，第 17 季交付第 25 架，第 18 季收尾到 28 架。

### 8.4 一旦出现就必须回头改设计的失败现象

| 现象 | 判定 | 修改方向 |
|---|---|---|
| 玩家不看工作项卡也能通关 | 流程层没有实际约束 | 提高前置链长度或收窄部门产能 |
| 所有部门都招满仍然缺人 | 数值过紧 | 提高部门基础产能或降低工作项需求 |
| 玩家说不出 TC 和 PC 的区别 | 学习目标未达成 | 在 TC 结算与 PC 结算各插一条强提示 |
| 拿到 TC 后玩家立刻开始交付 | 生产闸门失效 | 检查 `pc` 判定与交付条件 |
| 前 12 季玩家没有任何决策压力 | 前置太松 | 让设计、制造、试验三条线在 T4 同时争抢人力 |
