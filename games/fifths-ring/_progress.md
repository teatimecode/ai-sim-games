## 预算复盘

只在白盒试玩节点复盘了一次，没有到正式生产一半的节点，因为首版范围本身已压到四关。

- 单关制作成本主要花在规则边界而不是界面：三处返工（#1、#2、#4）都来自"规则读起来对、组合起来无解"，而不是渲染或交互。
- 结论：这类改编的成本重心在**把教材条文转成可判定约束**，且必须用求解器验证每一关有解，否则玩家会卡在无解关卡上。
- 因此没有加第五关，也没有做第三、第四类对位。若要继续，优先做第四类（留音），因为它复用同一骨架并新增一条"延留—解决"判定，不需要新数据。

## 预算复盘（第二轮）

- 本轮成本重心从「规则自洽」转到「一套判定要能撑起一类玩法」。拼音阶、和声、音集三类都做成了可解释的判定，每类只需一个纯函数加一个渲染器。

- 结论：这套结构可以继续按「一个纯函数判据 + 一个渲染器」的粒度扩张，第四类对位与十二音都符合这个形状。

# 第六轮：落地页与用户旅程

## 触发

真实反馈：打开就是地图，新玩家不知道这是什么游戏、自己是谁、总目标是什么、下一步点哪。

## 改了什么

| 项 | 改前 | 改后 |
|---|---|---|
| 入口 | 直接进地图 | 落地页：一句话定位、身份、总目标、五类动作、声音提示、六城区预览 |
| 主按钮 | 无 | 首访「开始旅程」，有存档「继续旅程」 |
| 清除进度 | 无 | 「重新开始」+ 二次确认，写明不可撤销，可取消 |
| 返回 | 无 | 地图右上「首页」回落地页 |
| 路由 | 只分地图/房间 | 新增 landing；有进度按上次页面恢复，不强制回落地页 |

## 途中修掉的两个缺陷

1. 点「开始旅程」后存档里 `view` 仍是 landing，刷新会弹回落地页；改成先定 view 再存，并在每次渲染地图与房间后落一次存档。
2. 全局缺 `[hidden]` 规则，被 `.reset-confirm` 的 `display:inline-flex` 覆盖，导致清除确认条默认可见、空按钮组留空行；补 `[hidden]{display:none !important}`。

## 验证

- 自动断言 428 → 450，新增路由、CTA、清除确认、无自动播放、`[hidden]` 守卫
- 旅程矩阵 10 步全通过：首访、开始、完成一关、刷新、回落地页、确认、取消、清除、清除后刷新、房间内刷新
- 三档视口落地页均无横向溢出，CTA 在首屏内
- 房间内刷新保持房间与已放音符

## 产物

- `design/INFORMATION_ARCHITECTURE.md`：五个页面的目标/入口/出口/反馈/状态，路由规则与存档清除流程
- `qa/verification.json`：新增 landing 与 journey 两段

# 第七轮：化身、印记与调性罗盘

## 范围

受控 MVP，只做 P0 与一个 P1 垂直切片，不引入自由漫游、属性、货币、账号。

| 项 | 内容 |
|---|---|
| 化身 | 纸偶式定制五组选项；地图锚点、三档提示、六枚印记载体 |
| 印记 | 六区各一枚，随 seals 点亮，地图与终页同步 |
| 校记 | 每区拿到印记后一次四选（修正/保留/并记/留白），只记录不改判定 |
| 终局 | 化身 + 个人符号 + 六印记 + 六条校记 + 姓名或留白 |
| 新玩法 | 调性罗盘两间房：最短的路、绕道关系调 |
| 规模 | 房间 24 → 26，可玩 15 → 17 |

## 途中修掉的缺陷

1. 顶部「回到环城」绕过 clearRoom，校记与终页都不触发。
2. renderCreator 覆盖宿主 class，容器一直带边框。
3. 批量替换把 `host.appendChild(box)` 改成自引用，定制面板整块不渲染。
4. 「体态」色块只设背景没写文字，显示为空。
5. 罗盘分发分支漏加，房间落到「仅讲解」。

## 验证

- 自动断言 450 → 490
- 化身：创建 → 确认 → 刷新保持；改形象不动进度
- 提示三档实测，第三档明确不替玩家选值
- 印记随城区完成点亮；校记四选写入存档；终页显示化身、印章、六印记、六条校记，留白可用
- 罗盘：走远被拒并定位到第 1 步；三步路径通过；关系调翻面四步通过
- 768 宽无横向溢出，罗盘环 430px，半身像可见
